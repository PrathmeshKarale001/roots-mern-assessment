1. `claimEmployeeCapacity(employeeId, startDate)` per D-07, RULE-02, and RULE-07:
   - Find employee by `_id`. If not found, throw `ApiError.notFound('Assigned employee not found')` (404).
   - If `employee.status === 'Inactive'`, throw `ApiError.badRequest('Cannot assign tasks to an Inactive employee')` (400) per RULE-02.
   - If `employee.status === 'On Leave'`:
     Normalize task `startDate` and `[employee.leaveStart, employee.leaveEnd]` via `parseUtcCalendarDate`.
     If `isDateInRangeInclusive(startDate, employee.leaveStart, employee.leaveEnd)` is true:
     Throw `ApiError.badRequest(`Employee is on leave during the task start date (${formatUtcDate(employee.leaveStart)} to ${formatUtcDate(employee.leaveEnd)})`)` (400) per RULE-02 and D-07.
   - If `employee.activeTaskCount >= 3`, throw `ApiError.badRequest('Employee already holds the maximum of 3 active tasks (Todo or In Progress)')` (400) per RULE-07 and D-07.
   - Execute single-document atomic conditional update:
     `const updated = await Employee.findOneAndUpdate({ _id: employeeId, activeTaskCount: { $lt: 3 }, $or: [{ status: 'Active' }, { status: 'On Leave', $or: [{ leaveStart: { $gt: startDate } }, { leaveEnd: { $lt: startDate } }] }] }, { $inc: { activeTaskCount: 1 } }, { new: true });`
   - If `!updated`: lost a concurrent race! Re-check employee state and throw `ApiError.badRequest('Employee already holds the maximum of 3 active tasks (Todo or In Progress)')` (400) per RULE-07.
   - Return `{ employee: updated, snapshot: { employeeId: updated.employeeId, fullName: updated.fullName, email: updated.email, department: updated.department, role: updated.role, isDeleted: false } }`.

2. `releaseEmployeeCapacity(employeeId)` per RULE-07 and D-08:
   - If `!employeeId` return;
   - Decrement atomic counter: `await Employee.findOneAndUpdate({ _id: employeeId, activeTaskCount: { $gt: 0 } }, { $inc: { activeTaskCount: -1 } });`.

3. `listTasks(query)`:
   - Execute `Task.find().populate('assignee', 'fullName email department role status activeTaskCount').sort({ createdAt: -1 })`.

4. `getTaskById(id)`:
   - Execute `Task.findById(id).populate('assignee', 'fullName email department role status activeTaskCount')`.
   - If not found, throw `ApiError.notFound('Task not found')`.

5. `createTask(data)` per D-06, RULE-04, and RULE-06:
   - Parse `startDate` and `dueDate` to UTC midnight via `parseUtcCalendarDate`.
   - If `data.assignee`: call `const { snapshot } = await claimEmployeeCapacity(data.assignee, data.startDate); data.assigneeSnapshot = snapshot;`.
   - Wrap persistence in `try/catch`:
     * Generate sequential ID: `const seq = await Counter.getNextSequence('taskId'); const taskId = `TSK-${String(seq).padStart(4, '0')}`;`.
     * Build task: `data.taskId = taskId`, `data.status = 'Todo'`, `data.priorityRank = PRIORITY_RANKS[data.priority] || 2`, `data.completedDate = null`.
     * `const task = await Task.create(data); return task;`
     * If create fails: call `if (data.assignee) await releaseEmployeeCapacity(data.assignee);` and rethrow.

6. `updateTask(id, data)` per RULE-05 and D-08:
   - Find existing task by ID: if not found, throw `ApiError.notFound('Task not found')`.
   - If `task.status === 'Completed'` or `task.status === 'Cancelled'`, throw `ApiError.badRequest('Completed or Cancelled tasks cannot be edited')` (400) per RULE-05 and D-08.
   - Handle date normalization if present.
   - Handle assignee changes on active tasks (`Todo` or `In Progress`):
     * If `data.assignee !== undefined && String(data.assignee || '') !== String(task.assignee || '')`:
       - If `data.assignee`: call `claimEmployeeCapacity(data.assignee, data.startDate || task.startDate)` to claim slot on new assignee and get new snapshot.
       - If `task.assignee`: call `releaseEmployeeCapacity(task.assignee)` to release old slot.
       - Update `task.assignee = data.assignee || null` and `task.assigneeSnapshot = newSnapshot || { employeeId: null, fullName: null, email: null, department: null, role: null, isDeleted: false }`.
     * If same assignee, but `startDate` is changing and assignee exists:
       - Fetch employee; if employee is `'On Leave'`, re-validate leave window `isDateInRangeInclusive(newStartDate, employee.leaveStart, employee.leaveEnd)`. If overlapping, throw `400`.
   - Update remaining editable fields (`title`, `description`, `department`, `priority`, `startDate`, `dueDate`).
   - If `priority` updated, update `priorityRank = PRIORITY_RANKS[priority]`.
   - Save and return task.

7. `updateTaskStatus(id, newStatus)` per RULE-04, RULE-05, RULE-06, and D-08:
   - Find task by ID: if not found, throw `ApiError.notFound('Task not found')`.
   - If `task.status === 'Completed'` or `task.status === 'Cancelled'`, throw `ApiError.badRequest('Completed or Cancelled tasks cannot transition to another status')` (400) per RULE-05 and D-08.
   - Check `STATUS_TRANSITIONS[task.status]`: if `!STATUS_TRANSITIONS[task.status].includes(newStatus)`, throw `ApiError.badRequest(`Invalid status transition from ${task.status} to ${newStatus}`)` (400) per RULE-04 and D-08.
   - Prepare update object: `const updateFields = { status: newStatus }; if (newStatus === 'Completed') updateFields.completedDate = new Date();`.
   - Atomic status compare-and-swap:
     `const updatedTask = await Task.findOneAndUpdate({ _id: id, status: task.status }, { $set: updateFields }, { new: true });`
     If `!updatedTask`, throw `ApiError.conflict('Task status was modified concurrently')` (409).
   - If previous status was active (`Todo` or `In Progress`) and new status is terminal (`Completed` or `Cancelled`) and `task.assignee`:
     `await releaseEmployeeCapacity(task.assignee);` per RULE-07 and D-08.
   - Return updated task.

8. `deleteTask(id)` per RULE-07 and D-08:
   - Find task: if not found, throw `ApiError.notFound('Task not found')`.
   - If (`task.status === 'Todo'` || `task.status === 'In Progress'`) && `task.assignee`:
     `await releaseEmployeeCapacity(task.assignee);` per RULE-07 and D-08.
   - Delete task and return.
